# 챗봇 서비스 기능의 Decisions 라우팅

작성일: 2026-10-09

챗봇은 최신 사용자 메시지를 Decisions로 분류한 뒤, 선택된 기능의 인자만 구조화 추출하여 서버에서 한 번 실행한다. 결과 설명에는 실행 도구를 제공하지 않는다. 이전의 자유로운 다중 도구 호출 루프를 대체한다.

## 분류 목록

| 보기 | 처리 |
| --- | --- |
| `get_study_context` | 현재 스터디의 공유 상태 조회 |
| `start_study` | 대기 중인 스터디 시작 |
| `close_topic` | 주제 종료 및 리뷰 준비 |
| `advance_topic` | 리뷰 승인·저장 및 다음 주제 생성 |
| `finish_study` | 스터디 종료 절차 진행 |
| `explain_word` | 단어 설명·개인 저장 |
| `learn_expression` | 표현 제안·개인 저장·공유 제안 |
| `list_my_learning` | 본인 학습 기록 조회·검색 |
| `request_sentence_feedback` | 특정 발화의 최신 보정문 피드백 |
| `accept_expression_share` | 직전 공유 제안 수락 |
| `decline_expression_share` | 직전 공유 제안 거절 |
| `general_chat` | 실행 없이 일반 답변 |
| `clarify_intent` | 의도·대상·복합 요청 확인 |

## 실행 규칙

- 서버의 현재 스터디 상태로 가능한 보기만 제공하며, 반환된 보기도 서버에서 다시 검사한다. 사용할 수 없는 기능을 다른 기능으로 대체하지 않도록 분류 프롬프트에 명시한다.
- 현재 소스의 분류 확신도 기준은 `0.5`다. 미달, 잘못된 응답, API 거절·실패·시간 초과는 실행 없이 되묻는다. 음성 발화 완료 기준 `0.85`와는 별도다. 모델의 의도 해석 품질은 별도 실사용 평가 대상이다.
- 공유 수락·거절은 본인·현재 스터디의 단일 pending 제안이 직전 성공한 챗봇 응답과 연결될 때만 보기로 제공한다. 여러 제안이 있거나 대상이 불명확하면 표현별 yes/no 버튼을 안내한다.
- 인자는 선택된 도구의 strict schema로 추출·검증한다. 대상이 불명확하면 `arguments: null`을 반환하도록 요청한다. 사용자 ID나 권한을 인자로 받지 않는다.
- 기존 도메인 명령의 사용자 권한, 주제 ID·전환 버전, 피드백 최신 revision 검증을 유지한다. 실패한 명령을 자동 재시도하지 않는다.
- 일반 답변 모델에는 도구를 제공하지 않는다. 도구 호출이 반환되면 실행하지 않고 메시지를 실패 처리한다. 이미 저장된 결과 ID는 유지한다.
- 사용자의 이전 대화는 본인·동일 스터디의 성공한 메시지 중 최근 20개만 모델에 제공한다. 과거 요청은 새 실행 권한이 아니다.

## 설정 및 검증

- 모델: 기존 `OPENAI_DECISION_MODEL` 사용.
- `CHAT_DECISION_TIMEOUT_MS`: 기본 10000ms, 허용 범위 1–60000ms. 음성 완료 판정 제한시간과 독립적이다.
- 2026-10-09 최초 AWS API 이미지와 발표 캡처에는 변경 전 분류 기준 `0.85`가 적용됐다. 실제 배포 버전은 [릴리스 기록](evidence/release.md)에서 확인한다.
- Mock AI도 같은 분류·인자 추출 인터페이스를 사용하며, 결정론적 개발 fixture이고 실제 모델 품질의 증거는 아니다.
- 전체 단위 테스트 301개 통과, 전체 workspace 타입 검사 통과. 테스트는 제공자 HTTP 계약, 실패·시간 초과, 상태별 실행 제한, 공유 연결, 개인정보 필터, 중단 후 늦은 결과 차단, Mock 전체 챗봇 흐름을 포함한다.
- 이번 변경의 실제 OpenAI 호출 및 브라우저 검증은 실행하지 않았다.
