# 사람 간 대화에 집중하는 AI 영어 스터디 서비스

상태: 주요 기능과 구현 제약 확정 · 세부 동작 인터뷰 진행 중

## 목표와 배경

`ai-for-human-life` 트랙에 맞춰, 사람끼리 진행하는 영어 스터디에서 참여자가 서로의 대화에 집중할 수 있도록 AI가 돕는 서비스를 기획하고 있다. 사용자가 제시한 트랙의 취지는 학습자에 맞는 설명·연습·피드백과 교육 현장 업무 지원이다.

문제의식은 AI의 발전으로 사람 중심의 학습이 점차 AI와의 학습으로 대체되고 있다는 것이다. AI 시대에도 인간관계는 중요한 가치이며, 이 서비스는 사람을 학습 상대로 두고 AI가 대화와 학습을 지원하도록 하려는 의도에서 출발한다.

대상은 사람끼리 영어 스터디를 진행하는 참여자다. 구체적인 연령과 영어 수준은 미정이다.

## 참여 환경과 입력 전제

- 참여자들은 같은 공간에서 직접 대화한다. 서비스 내 통화 기능은 구현 범위에서 제외한다.
- 각 참여자는 자신의 노트북을 사용한다.
- 공통 스터디 화면은 각자의 기기에서 동기화된다.
- AI 챗봇은 참여자별 개인용이다.
- 각 참여자는 자신의 노트북 마이크로 음성을 입력한다.
- 대화 중에는 각 참여자의 마이크를 계속 켜둔다.
- 사용자 지정 MVP 전제: 각 노트북 마이크에는 해당 참여자 본인의 목소리만 입력되며, 다른 참여자의 목소리는 들어가지 않는다고 가정한다.
- 발화자 구분은 참여자별 입력 출처에 맡긴다. 음성 모델이 발화자를 구분하는 방식은 전제하지 않는다.

## 가입과 스터디 생성

- 사용자는 이름과 아이디를 입력해 가입한다. 아이디는 중복을 허용하지 않는다.
- 스터디는 누구나 생성할 수 있다.
- 스터디 생성 시 함께할 참여자들의 사용자 아이디를 입력한다.
- 스터디가 생성되면 지정된 다른 참여자들의 사이트 화면에 모달 오버레이를 표시한다.
- 해당 참여자는 모달의 ‘참여하기’ 버튼을 눌러 스터디에 입장한다.
- 생성된 스터디는 1회성이다.

## 확정된 구현 범위와 제약

- 이 문서에 기재된 주요 화면과 핵심 기능은 모두 구현하기로 확정된 사항이다. 구현 여부를 정할 후보 목록이 아니다.
- 짧은 시간 내에 실제로 동작하는 MVP를 만든다. 주요 기능들은 반드시 동작해야 한다.
- 프로덕션 환경에서 고려할 보안, 실패 시 재시도 등의 정책은 이번 구현 범위에서 제외한다.
- AI 모델은 전부 OpenAI에서 제공하는 모델만 사용한다.
- 배포는 AWS로 진행한다.
- 구체적인 개발 기간과 팀 구성은 아직 확인되지 않았다.

### 실제로 동작해야 하는 MVP의 최소 기준

- 두 기기에서 같은 주제와 진행 상태가 실제로 동기화된다.
- 실제 마이크 입력과 OpenAI 호출로 전사·인식 오류 보정·피드백·이미지 생성이 동작한다.
- 보정문 수정 후 재요청한 피드백이 해당 문장에 반영된다.
- 개인 챗봇과 개인 학습 기록이 사용자별로 구분된다.
- 공유에 동의한 표현이 공통 화면과 다음 주제 생성에 반영된다.
- 중복 클릭으로 다음 주제가 두 번 생성되지 않도록 최소한의 처리를 한다.
- 생성 중·완료·실패를 구분해서 표시한다. 실패 시 자동 재시도 정책은 구현하지 않는다.

위 기준과 함께 이 문서에 명시된 주요 화면과 핵심 기능을 모두 구현한다.

## Astra에 맡길 범위: 인터뷰를 통한 기획 구체화

아래 확정된 기능을 바탕으로 사용자와 인터뷰하여 사용자 흐름과 기능별 동작을 구체화한다. 임의의 가정을 추가하지 않고 사용자가 확인한 실제 구현사항만 문서에 반영한다. 사용자가 명시적으로 지정한 가정은 MVP 전제로 구분해 기록한다. 확인되지 않은 사항은 임의로 결정하지 않고 인터뷰로 확인한다.

요청할 산출물은 다음과 같다.

- 세 가지 주요 화면의 구성과 스터디 참여자의 사용자 흐름.
- 전사, 인식 오류 보정, 주제 종료 후 전사 비교·수정과 AI 피드백, 상황 이미지·문장 제안, 챗봇 조작이 연결되는 기능별 동작 정의.
- 확정된 필수 기능을 모두 포함하는 MVP 구현사항 정리.

## UI 구성과 기능 조작 원칙

- 화면의 잡다한 요소를 최소화하여 참여자들이 사람 간 대화에 집중할 수 있게 한다.
- 대부분의 기능은 개인용 사이드 챗봇에 자연어로 요청해 조작할 수 있게 한다. 챗봇의 기능 실행 결과는 관련 UI에 반영한다.
- 화면 요소를 최소화하면서 챗봇으로 대부분의 기능을 조작하는 경험을 사용자가 의도한 서비스 차별점으로 제시한다.
- 구체적인 버튼 구성과 배치는 지금 확정하지 않는다. 사용자가 구현된 화면을 확인한 뒤 조정한다. 챗봇만으로 모든 기능을 조작해야 한다는 원칙으로 제한하지 않는다.

## 스터디 진행 흐름

스터디의 시작과 종료는 사람이 지정한다. 참여자 누구나 스터디 시작, 주제 대화 종료, 다음 주제 이동, 스터디 종료를 실행할 수 있다. 스터디가 종료될 때까지 이미지 또는 문장으로 주제를 추천하고, 그 주제로 대화하는 과정을 반복한다.

사람이 스터디를 시작하면 경험·관심사 기반의 첫 주제로 대화를 시작한다. 각 주제의 대화가 끝나면 전사와 피드백을 검토하고 필요한 내용을 수정한다. 다음 주제로 넘어가겠다는 요청이 들어오면 피드백을 최종 승인 처리하고 다음 주제로 이어간다. 다음 주제에도 이미지 또는 문장과 대화 진행 지시를 제공하며, 사람이 스터디를 종료할 때까지 이 흐름을 반복한다.

스터디를 끝낼 때도 마지막 주제의 피드백을 검토하고 최종 승인한다. 승인된 단어·표현을 해당 발화자의 개인 학습 기록에 자동 저장한 뒤 스터디를 종료한다.

## 핵심 기능

### 1. 개인별 경험·관심사 기록

참여자의 경험과 관심사를 개인별로 기록한다. 이 정보는 영어 표현을 사용할 수 있는 상황 이미지를 생성할 때 활용한다.

입력 UX는 자유 기록을 기본으로 한다. 구체적인 상황을 담을 수 있도록 다음 흐름을 제공한다.

1. 처음에는 입력창 하나를 보여주고, 최근 있었던 일이나 기억에 남는 경험을 자유롭게 작성하게 한다. “어디서, 누구와, 어떤 일이 있었나요?”라는 짧은 힌트로 작성을 돕는다.
2. 기록에 구체적인 상황 정보가 부족하면 AI가 보충 질문을 자동으로 제시한다. 예를 들어 “부산에 다녀왔어요”라는 기록에는 “여행 중 기억에 남는 일이 있었나요?”라고 질문한다.
3. 보충 질문에 대한 답변은 선택사항이다. 사용자는 답하지 않고도 정리·저장 흐름을 계속 진행할 수 있다. 이미 충분히 구체적인 기록은 바로 정리한다.
4. AI는 기록과 사용자가 답한 내용을 바탕으로 관심사와 경험의 맥락을 정리한다. 장소·사람·사건·행동 등 기록에 있는 정보를 활용하며, 사용자가 말하지 않은 사건을 경험에 추가하지 않는다.
5. 사용자는 원문과 정리된 경험을 확인하고 필요한 내용을 수정한 뒤 저장한다.
6. 저장된 경험은 카드로 모아 보여준다. 사용자는 기존 경험을 수정하거나 새 경험을 추가할 수 있다.

### 2. 공통 스터디 화면과 전사·인식 오류 보정

참여자들은 각자의 노트북에서 동일한 대화 주제가 동기화된 공통 화면을 보며 스터디를 진행한다.

영어 표현이 막혀 중간에 한국어로 설명하거나 잘못된 영어 표현을 사용한 경우에도, 그 발화를 원문 전사에 그대로 드러낸다. AI는 전사문 각 라인 아래에 인식 오류를 보정한 문장을 표시한다.

여기서 보정은 전사 모델이 실제 발화를 잘못 기록한 부분을 바로잡는 것이다. 예를 들어 실제로 말한 ‘해커톤’을 ‘핵톤’으로, ‘human’을 ‘흠’으로 기록한 경우를 다룬다. 화자가 실제 사용한 틀린 영어 표현을 올바른 영어로 바꾸는 작업은 다음 기능에서 별도로 수행한다.

원문 전사와 인식 오류 보정문은 모두 대화 중 실시간으로 함께 표시하여, 사용자가 AI가 바꾼 내용을 확인할 수 있게 한다.

실시간 전사·보정문은 스터디 화면 하단에 표시한다. 노래 가사가 넘어가듯 발화 진행에 따라 문장이 순차적으로 넘어가는 방식으로 보여준다.

### 3. 주제별 대화 종료 후 전사 비교·수정과 AI 피드백

AI 분석 피드백은 해당 주제의 대화가 끝난 후 진행한다.

주제 대화가 끝난 뒤, 스터디 화면 안에서 원문 전사와 인식 오류 보정문을 비교하고 피드백을 검토할 수 있도록 한다. 보정문을 바탕으로 올바른 영어 표현과 대체 표현 등을 제안한다.

화면은 한 문장마다 다음 내용을 묶고, 이 묶음을 세로 방향으로 나열한다.

- 원문 전사.
- 인식 오류 보정문. 참여자 누구나 본인과 다른 참여자의 발화에 대한 보정문을 직접 편집할 수 있다.
- 해당 문장에 피드백이 있으면 보정문 아래에 한 줄 요약을 토글 형식으로 표시한다. 요약은 ‘몰랐던 표현’, ‘대체 가능한 표현’ 등 피드백의 내용을 나타내며, 펼치면 실제 피드백 내용을 보여준다.

사용자가 보정문을 편집하면 수정된 문장 옆에 피드백 재요청 버튼을 둔다. 버튼을 실행하면 수정된 문장을 바탕으로 해당 문장의 피드백을 즉시 갱신한다.

사용자가 다음 주제로 넘어가겠다고 하면 피드백 내용을 최종 승인 처리한다. 다음 주제로 넘어갈 시점에 대한 참여자 간 조율은 사람들에게 맡기며, 서비스가 별도로 관리할 대상으로 삼지 않는다.

최종 승인된 피드백의 단어·표현은 해당 발화자의 개인 학습 기록에 자동 저장한다. 다음 주제로 이동할 때와 마지막 주제 검토를 마치고 스터디를 종료할 때 모두 적용한다.

표시되는 정보는 다음 세 단계로 구분한다.

- 원문 전사: 한국어 사용이나 잘못된 영어 표현을 포함한 발화의 전사 결과.
- 인식 오류 보정문: 전사 모델이 잘못 기록한 부분을 실제 발화에 맞게 바로잡은 문장.
- 학습용 영어 표현: 보정문을 바탕으로 제안한 올바른 영어 표현과 대체 표현.

### 4. 학습 표현과 개인 맥락을 활용한 상황 이미지·문장 제안

기본적으로 참여자 전체의 경험·관심사를 바탕으로, 이전 대화에서 발견된 학습할 영어 표현을 자연스럽게 사용할 수 있는 상황을 이미지로 생성한다. 경험·관심사는 기본 생성에서도 필요한 근거이며, AI가 참여자의 맥락과 무관한 상황을 임의로 생성하는 방식은 의도하지 않는다.

사용자가 특정 참여자의 이름을 호명하며 AI에게 요청하면, 해당 참여자의 경험·관심사를 기준으로 상황 이미지를 생성한다.

첫 대화는 이전 대화에서 얻은 학습 표현 없이 참여자의 경험·관심사를 바탕으로 시작한다.

학습할 표현은 있지만 연결할 경험이 없는 경우에는 이미지 대신 해당 표현을 활용할 수 있는 문장을 제안한다. 이 문장은 토익스피킹(TOEIC Speaking) 시험 유형을 참고한다.

모든 주제에는 이미지나 문장뿐 아니라, 참여자들이 무엇에 대해 어떤 방식으로 대화해야 하는지도 함께 제공한다. 이 대화 진행 지시는 토익스피킹 문제처럼 제시한다. 이미지로 제공하는 주제와 문장으로 제공하는 주제에 모두 적용한다.

### 5. 사이드 챗봇을 통한 기능 조작

스터디 화면 옆에 참여자별 개인용 챗봇을 둔다. 사용자가 자연어로 다음 행동을 지시하면 관련 기능을 실행하고 UI에 즉시 반영한다. 개인 학습용 답변은 해당 사용자에게 제공하며, 공통 화면에 공유하는 동작은 아래 흐름을 따른다.


| 사용자 요청 예시                 | 기대 동작                                                                                              |
| ------------------------- | -------------------------------------------------------------------------------------------------- |
| “다음 주제로 넘어갈게”             | 피드백 내용을 최종 승인 처리한다.                                                                                |
| “다음 주제 만들어줘”              | 참여자 전체의 경험·관심사를 바탕으로 학습 표현을 자연스럽게 사용할 상황 이미지를 생성한다. 학습 표현에 연결할 경험이 없으면 토익스피킹 시험 유형을 참고한 문장으로 제안한다. |
| 특정 참여자의 이름을 호명하며 주제 생성 요청 | 해당 참여자의 경험·관심사를 기준으로 상황 이미지를 생성한다. 학습 표현에 연결할 경험이 없으면 같은 문장 제안 방식을 적용한다.                           |
| “\~단어 뜻 뭐야?”              | 요청한 사용자에게 개인적으로 답변하고, 개인 학습 단어에 추가한다.                                                              |
| “\~표현은 영어로 어떻게 해?”        | 답변 내용을 개인 학습에 추가하고, “스터디 내용에 반영할까요?”라는 yes/no 선택을 제공한다.                                            |
| 표현 공유 질문에 yes 선택          | 해당 표현을 스터디 UI에 반영하고 다음 주제를 만들 때 참고한다.                                                              |


위 표의 주제 생성 요청에는 이미지 또는 문장과 함께 대화 진행 지시를 제공하는 동작이 포함된다.

참여자는 스터디 화면에서 자연어 채팅으로 필요한 기능을 조작한다. 전사, 표현 학습, 이미지 생성 등을 위해 다른 서비스로 이동할 필요가 없는 경험을 지향한다.

## 의도한 차별점

1. **사람이 학습 상대가 된다.** AI가 발전한 환경에서도 사람 간 대화와 관계를 중심에 두고 학습을 지원한다.
2. **전사 오류 보정과 학습용 표현 제안을 구분하고 그 과정을 보여준다.** 불완전한 전사문을 LLM에 전달하면 실제 발화와 다른 의미로 해석될 수 있고, 사용자는 중간 과정을 모른 채 불필요한 답변을 받을 수 있다는 문제의식이 있다. 원문 전사와 인식 오류 보정문을 함께 표시하며, 주제별 대화 종료 후 비교·수정 화면을 제공해 사용자가 차이를 확인하고 수정할 수 있도록 한다.
3. **화면 요소를 최소화하고, 대부분의 기능을 챗봇으로 조작한다.** 개인용 사이드 챗봇의 자연어 요청을 개인 학습과 공통 스터디 UI에 연결해 조작을 간편하게 한다. 참여자들이 사람 간 대화에 집중하면서 한 서비스 안에서 필요한 작업을 처리하는 경험을 지향한다.
