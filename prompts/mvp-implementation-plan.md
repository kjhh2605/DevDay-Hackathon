# MVP 구현·배포를 위한 아키텍처 선정 및 작업 문서 작성

상태: 최종

## 목표

사람끼리 진행하는 영어 스터디를 AI가 지원하는 서비스의 완료된 PRD를 바탕으로, 동작 가능한 MVP를 빠르게 만들 수 있도록 아키텍처와 기술 스택을 선정하고 구현부터 AWS 배포까지 진행할 작업 문서를 작성한다. 여러 세션에서 병렬로 작업할 수 있도록 각 세션에 전달할 문서도 제작한다.

## Astra에 맡길 범위

아키텍처와 기술 스택 검토·선정, 구현·배포 계획 수립, 세션별 작업 문서 작성을 맡긴다. 이번 요청의 산출물은 문서이며, 실제 제품 구현과 AWS 배포 실행은 포함하지 않는다.

- PRD: 프로젝트의 `docs/prd.md`. 사용자가 작성 완료된 PRD로 지정했으며, 기능 범위와 MVP 제약의 기준으로 삼는다.
- 프로젝트 경로: `/Users/gnar/orca/projects/DevDay-Hackathon`
- 프론트엔드 디자인 시스템: 프로젝트의 `design/` 디렉터리
- 사용할 SEED Design 에셋: <https://seed-design.io>
- 이 지시서에는 `docs/prd.md`를 읽고 확인한 내용을 반영했다. `design/` 내부 자료와 SEED Design 사이트의 내용은 아직 확인하지 않았으며, 실제 작업 문서를 작성할 때 확인해 반영한다.

## 확정 요구사항

- 프론트엔드는 React + TypeScript로 제작한다.
- 프론트엔드에 `design/`의 디자인 시스템과 SEED Design 에셋을 사용한다.
- 배포 대상은 AWS다.
- 빠르게 동작 가능한 MVP를 만드는 데 적합한 아키텍처와 기술 스택을 선정한다.
- 참여자별 개인 챗봇이 자연어 요청으로 제품 기능을 실행하고 결과를 관련 UI에 반영하도록 구성한다. 주제 진행·생성, 단어·표현 학습 및 저장, 공유 동의에 따른 공통 화면 반영 등 구체적인 동작은 PRD를 따른다.
- 여러 세션에 작업을 나누어 병렬 진행할 수 있도록 세션별 작업 문서를 만든다.

### PRD에서 유지해야 할 핵심 제약

- AI 모델은 모두 OpenAI에서 제공하는 모델을 사용한다.
- PRD에 명시된 주요 화면과 핵심 기능은 모두 구현 대상이다. 빠른 MVP를 이유로 확정 기능을 임의로 제외하지 않는다.
- 같은 공간에 있는 참여자가 각자의 노트북을 사용하며, 공통 화면과 진행 상태는 두 기기에서 실제로 동기화되어야 한다. 개인 챗봇과 학습 기록은 사용자별로 구분한다.
- 실제 마이크 입력과 OpenAI 호출로 전사·인식 오류 보정·피드백·이미지 생성이 동작하고, 필요한 학습 데이터를 저장하고 다시 조회할 수 있어야 한다.
- 각 마이크에는 해당 참여자의 목소리만 들어온다는 사용자 지정 MVP 전제를 유지한다. 서비스 내 통화 기능은 제외한다.
- PRD에서 제외한 프로덕션 운영 정책과 부가 기능은 범위에 추가하지 않는다. 중복 주제 생성 방지, 생성 중·완료·실패 표시 등 PRD가 유지하도록 정한 최소 동작은 포함한다.

## UI/UX 수정과 백엔드 계약

사용자가 UI/UX를 직접 보면서 자주 수정할 예정이다. 백엔드와의 계약을 유지하면서 프론트엔드에서 화면과 인터랙션을 자유롭게 변경할 수 있도록 설계한다.

이를 위해 프론트엔드와 백엔드가 공유할 계약과, 그 계약 안에서 프론트엔드가 독립적으로 바꿀 수 있는 범위를 작업 문서에 명확히 한다. 계약을 정의하고 유지하는 구체적인 방법은 아키텍처 선정 과정에서 결정한다.

## 요청하는 산출물

1. **아키텍처·기술 스택 선정 문서**: PRD와 위 요구사항을 바탕으로 전체 구성을 정하고, 빠른 MVP 구현 및 잦은 UI/UX 수정에 적합한 선정 이유를 설명한다. 아직 정하지 않은 백엔드 기술, AWS 서비스 구성, 챗봇 기능 실행 방식도 검토해 선정한다.
2. **구현·배포 작업 문서**: 선정한 구성으로 MVP 구현부터 AWS 배포까지 진행할 작업과 의존 관계를 정리한다. 프론트엔드와 백엔드의 계약 및 프론트엔드 독립 수정 방식을 포함한다.
3. **세션별 작업 지시 문서**: Astra가 작업 범위와 의존 관계에 맞춰 세션 수와 분할을 선정한다. 각 세션이 맡을 범위, 참고 자료, 산출물, 다른 세션과 맞춰야 할 계약과 의존 관계를 명확히 하여 병렬 작업에 바로 사용할 수 있게 작성한다.

## 검토할 사항

- 챗봇의 UI 조작·기능 실행을 위해 MCP가 필요한지 검토한다. 사용자는 MCP가 필요할 것으로 예상하지만, 도입을 확정한 상태는 아니다.
- 챗봇이 어떤 방식으로 UI와 기능에 연결되어야 빠르게 동작 가능한 MVP를 만들면서도 잦은 프론트엔드 수정을 수용할 수 있는지 검토한다.
